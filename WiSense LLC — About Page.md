## Founder

**Nicholas Wittle** — Founder & Builder, WiSense LLC

United States Marine Corps veteran — Huey crew chief. Before building software, spent years in the Corps learning that a flight plan is not a suggestion: every leg, every waypoint, every timing window exists for a reason.

That doctrine is the foundation of how he builds. Every product at WiSense solves one specific problem for a specific person, completely. No speculation, no feature demos, no half-finished implementations delivered as output.

**Product origins:**
- Horizon came from watching couples negotiate trips in group texts
- Apex came from his wife needing a simpler way to check her work schedule
- Each venture started with a real problem, understood deeply, and solved completely

**Current state:** WiSense is a one-person studio right now. That will change — but the standard won't.

## The WiSense Standard (4 principles)

| Principle | Description |
|-----------|-------------|
| 🎯 **One Problem, Completely** | We don't ship three half-finished tools. We ship one tool that does what it says, end to end, for the person who needs it. |
| 🚫 **No Speculation** | We don't build for imaginary future requirements. We build for the problem in front of us, then write the next brief. |
| 📦 **Ship It Complete** | Every release is production-ready. No stubs, no TODO scaffolding, no features labeled "coming soon" as placeholders for things we didn't finish. |
| 🔁 **Iterate from Real Use** | After a complete v1 ships, the next iteration is driven by observed usage — not speculation about what users might want. |

These principles directly map to the WiSense Minimalist Standards in the governance protocol (see [[Governance Protocol]]) — "Write only what the task requires. No speculative features or preemptive abstractions. No stubs, TODOs, or partial implementations delivered as output."
