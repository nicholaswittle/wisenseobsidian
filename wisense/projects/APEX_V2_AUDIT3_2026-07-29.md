## Executive Summary & Scope

This audit evaluates the new feature surface introduced up to HEAD `067092e`: `staff_aliases`, `venue_hours`, `usage_events`, the revised `shifts` policy set, `apex_claim_call_out`, `@roster.local` placeholder profiles, new client write paths, and the cost/abuse posture of the Anthropic-powered `parse-schedule` and `parse-menu` Edge Functions.

> **Verification Limit Notice:** The CLI database connection operates as `postgres` where `auth.uid()` is `NULL`. RLS policies and `SECURITY DEFINER` functions were verified **structurally** by inspecting SQL definitions, `pg_policies` catalog entries, and Edge Function TypeScript source code. Runtime session behavior for signed-in JWT users was evaluated analytically based on structural guarantees.

## Detailed Section Audit

### 1. `staff_aliases` & `apex_set_staff_alias`
- **Location:** Table `public.staff_aliases`, Policy `staff_aliases_select`, RPC `apex_set_staff_alias` (`20260802180000`)
- **How Verified:** Structural inspection of SQL definition and `pg_policies`.
- **Findings:**
  - **Manager Gating:** `apex_set_staff_alias` requires `has_role(p_org, 'manager')` (line 54) and RLS `staff_aliases_write` requires `has_role(organization_id, 'manager')`.
  - **Cross-Venue Overwrites:** A manager passing `p_org` for a venue they do not manage triggers `manager_required` exception in `apex_set_staff_alias`. They cannot overwrite aliases outside their managed venues.
  - **Read Scoping:** Policy `staff_aliases_select` uses `organization_id = apex_current_org_id() OR is_super_admin()`. Members can only read aliases for their active venue.

### 2. `venue_hours` & `apex_set_venue_hours`
- **Location:** Table `public.venue_hours`, RPC `apex_set_venue_hours` (`20260802200000`)
- **How Verified:** Structural inspection of SQL definition and `lib/features/schedule/photo_import_screen.dart`.
- **Findings:**
  - Writes are gated by `has_role(p_org, 'manager')`. `p_weekday` is constrained to `1..7`.
  - In `photo_import_screen.dart:120`, if `closed == true` or `opens == null`, hours loading skips the day cleanly. Inverted times (e.g. `opens > closes`) do not break `parse-schedule`; the prompt uses hours as a heuristic prompt line.

### 3. `usage_events` & `apex_activation_summary` Privacy
- **Location:** Table `public.usage_events`, RPC `apex_activation_summary` (`20260802190000`), `lib/core/usage.dart`
- **How Verified:** Structural analysis of SQL policies, `usage.dart`, and database function definitions.
- **Findings:**
  - **Identity Forgery Protection:** `usage_events_insert` policy enforces `WITH CHECK (organization_id = apex_current_org_id() AND user_id = auth.uid())`. Clients cannot forge another user's activity.
  - **Read Privacy:** `usage_events_select` requires `has_role(organization_id, 'manager') OR is_super_admin()`. Plain staff cannot read colleagues' activity rows.
  - **Data Minimization:** `usage.dart` logs only screen routes, event names, and numeric counts (`shifts: N`). No user-authored text (messages, notes, customer data) reaches `detail` or `target`.
  - **`apex_activation_summary` Protection:** Contains `WHERE is_super_admin()`. Non-super-admins calling the RPC receive 0 rows.

### 4. `shifts` Policy Set & `apex_claim_call_out`
- **Location:** PostgreSQL policies on `shifts`, RPC `apex_claim_call_out` (`20260802210000`)
- **How Verified:** Catalog query of `pg_policies` on `shifts` and structural inspection of `apex_claim_call_out`.
- **Findings:**
  - **`shifts staff claim open` Unconstrained `WITH CHECK` (CRITICAL):** Migration `20260802210000` dropped `shifts org all` and added `shifts manager write`. However, policy `shifts staff claim open` (created in `20260802100000`) was **not dropped**. Its `USING` clause permits updates where `staff = 'Open'`, but its `WITH CHECK` clause is `(organization_id = apex_current_org_id())`. Any authenticated staff member can execute a direct PostgREST `UPDATE` on open shifts to change shift dates, times, or assign the shift to any arbitrary person.
  - **`apex_claim_call_out` Safety:** Checks `is_member(v_org)` (line 39), `v_owner <> auth.uid()` (line 46), and runs inside a single PL/pgSQL transaction block. If any step fails, the entire claim rolls back atomically.

### 5. Placeholder Profiles (`@roster.local`) without Auth User
- **Location:** `public.profiles` rows (`kim@roster.local`, `marsha@roster.local`, etc.)
- **How Verified:** SQL query against `profiles` vs `auth.users` and analysis of `apex_handle_new_user()`.
- **Findings:**
  - **Duplicate Profile Creation on Signup (HIGH):** When a staff member (e.g. Kim) registers with her real email (`kim@gmail.com`), `apex_handle_new_user()` executes `INSERT INTO profiles` with her new `auth.users.id`. This creates a **second profile** row.
  - **Calculation Corruption:** Shift assignments and roster names referencing the placeholder profile (`ea6da912-...`) do not match the new user's `auth.uid()`. Tip allocations (`apex_calculate_hours_for_user`) and labor cost tracking calculate to **0 worked hours** or omit the employee.
  - **Privilege Escalation:** Placeholder profiles have no `auth.users` row and no credentials. They sit inert and cannot be logged into.
  - **UUID Collision Risk:** Near zero ($1 / 2^{122}$).

### 6. Client Write Paths Server-Side Backing
- **Location:** `lib/features/schedule/photo_import_screen.dart`, `schedule_screen.dart`
- **How Verified:** Code search for client writes against DB policies.
- **Findings:** Schedule edits, deletes, photo-import publishes, and alias updates write to `shifts`, `staff_aliases`, and `venue_hours`. All three tables are protected server-side by `has_role(organization_id, 'manager')` RLS policies.

### 7–10. Edge Functions, Cost & Abuse (`parse-schedule` / `parse-menu`)
- **Location:** `supabase/functions/parse-schedule/index.ts`, `parse-menu/index.ts`
- **How Verified:** Code inspection of Edge Function handlers.
- **Findings:**
  - **Unbound Anthropic Spend & No Rate Limiting (CRITICAL):** `parse-schedule` and `parse-menu` have **no rate limiting, per-org quotas, or payload size limits**. Furthermore, neither function validates the `Authorization` header or verifies manager role before calling Anthropic. Any client can script loop requests with `imageBase64`, invoking `claude-sonnet-4-5` and draining prepaid Anthropic credits.
  - **Prompt Injection & Token Inflation (HIGH):** `body.roster` is injected into the Claude prompt without string sanitization or array length caps. Malicious text in `roster` can hijack prompt instructions or inflate prompt tokens.
  - **`extractJson` Behavior (MEDIUM):** `extractJson` uses `raw.lastIndexOf("}")` to find the last valid JSON object. If a model output appends commentary with trailing braces, `extractJson` parses the trailing object instead of the schedule JSON.
  - **Secret Isolation:** `ANTHROPIC_API_KEY` is isolated in Deno environment variables and absent from all client bundles.

### 11–12. Regressions & Column Grants
- **Findings:**
  - **Shift Writes:** Manager-only shift policies work as intended, but active policy `shifts staff claim open` leaves open shifts vulnerable to arbitrary updates by plain staff.
  - **Column Grants:** All columns on newly added tables (`staff_aliases`, `usage_events`, `venue_hours`) are granted SELECT to `authenticated`. `profiles.hourly_rate` remains hidden (`auth_select: false`).

## 🏆 Ranked Findings

### 1. 🔴 CRITICAL — Uncapped Edge Function Invocations & Unbound Anthropic Credit Drain
- **Location:** `supabase/functions/parse-schedule/index.ts` & `parse-menu/index.ts`
- **How Verified:** Code inspection of Edge Function handlers.
- **Concrete Impact:** `parse-schedule` and `parse-menu` do not validate user JWTs, enforce manager roles, apply rate limits, or cap image payload sizes. A single malicious or buggy client can send continuous `imageBase64` requests to `claude-sonnet-4-5`, exhausting your prepaid Anthropic balance in minutes.
- **Proposed Fix:** Add JWT verification (`authHeader`), manager role check (`has_role`), rate limiting (e.g. 5 requests / min per org), and payload size validation (max 5MB) in the Edge Function header.
- **v1 Risk:** None (v1 does not call these Edge Functions).

---

### 2. 🔴 CRITICAL — Unconstrained `WITH CHECK` on `shifts staff claim open` Policy
- **Location:** RLS Policy `shifts staff claim open` on `public.shifts`
- **How Verified:** Structural query of `pg_policies` on `shifts`.
- **Concrete Impact:** Migration `20260802210000` dropped `shifts org all` but left `shifts staff claim open` active. Its `USING` clause matches `staff = 'Open'`, but its `WITH CHECK` is `(organization_id = apex_current_org_id())`. A plain staff member updating an open shift can reassign it to anyone, alter shift dates, or change start/end times.
- **Proposed Fix:** Drop policy `shifts staff claim open` completely, forcing all shift coverage claims through the `apex_claim_call_out` RPC.
- **v1 Risk:** Low.

---

### 3. 🟠 HIGH — Prompt Injection & Unbounded Token Inflation in `parse-schedule`
- **Location:** `supabase/functions/parse-schedule/index.ts:79-113`
- **How Verified:** Structural inspection of prompt construction.
- **Concrete Impact:** `body.roster` accepts an arbitrary array of strings from the client and interpolates them directly into the Anthropic prompt. A malicious string inside `roster` can hijack model instructions, or an oversized array can inflate token usage and trigger API errors.
- **Proposed Fix:** Cap `roster` length (max 50 names), sanitize strings (alpha-numeric + spaces only, max 40 chars per name), and wrap in strict structural XML tags (`<roster_reference>`).
- **v1 Risk:** None.

---

### 4. 🟠 HIGH — Duplicate Profile Creation & Calculation Corruption for `@roster.local` Placeholders
- **Location:** `public.profiles` & `apex_handle_new_user()`
- **How Verified:** SQL query against `profiles` vs `auth.users` and function tracing.
- **Concrete Impact:** Placeholder profiles (`kim@roster.local`) have no `auth.users` entry. When staff register with real emails, `apex_handle_new_user()` creates a second profile (`UUID_NEW`). Shift histories, tip allocations, and labor cost metrics linked to the placeholder profile ID become fragmented or calculate to 0 for the real user.
- **Proposed Fix:** In `apex_handle_new_user()`, check for existing placeholder profiles by name/email in the organization and merge/claim the placeholder ID during signup.
- **v1 Risk:** Low.

---

### 5. 🟡 MEDIUM — `extractJson` Last-Match Priority Vulnerability
- **Location:** `supabase/functions/parse-schedule/index.ts:30-49`
- **How Verified:** Code inspection of `extractJson`.
- **Concrete Impact:** Scanning backward from `raw.lastIndexOf("}")` returns the last parseable JSON block. If model output includes appended text containing JSON braces, `extractJson` parses the appended block instead of the schedule payload.
- **Proposed Fix:** Parse JSON using explicit code block demarcators (```json ... ```) or scan from the first `{`.
- **v1 Risk:** None.

---

### 6. 🔵 LOW — Inverted Time Window Validation in `venue_hours`
- **Location:** PostgreSQL Function `apex_set_venue_hours` (`20260802200000`)
- **How Verified:** Structural function inspection.
- **Concrete Impact:** `apex_set_venue_hours` validates `p_weekday BETWEEN 1 AND 7`, but does not validate `p_opens < p_closes`. Setting inverted hours without setting `closed = true` relies on client-side fallbacks.
- **Proposed Fix:** Add check `opens < closes` or require an explicit overnight flag.
- **v1 Risk:** None.
